Headline findings

BLOCKER
The published Q1 snapshot is stale and the freshness check doesn't catch it. platform_affordance_evidence.json (generated 2026-11-12, served by the MCP tool) was built from candidates.json dated 2026-10-20, which lists 3,183 cases. Rebuilding candidates from the live DB gives 3,083. 361 stale IDs are not in the fresh pool and 261 fresh cases are missing. rebuild_platform_affordance_evidence.py --check reports decision=current because it compares only the evidence file's case count and fingerprint, never the candidate list. Effect: 941 stated cases (non-generic) published vs 1,123 fresh. verified
BLOCKER
NCMEC case IDs were renumbered between snapshots. For 1,421 old NCMEC evidence quotes whose ID still exists, only 92 still appear in that ID's text. A content crosswalk maps 976 old NCMEC IDs, and 924 of them now sit under a different ID (renumbered within the same year). Examples: ncmec_2025_706 was a Snapchat extradition case and is now a Google Drive possession case. PACER graph ncmec_2023_224 (Kik, 13-year-old) now resolves to an HSI possession plea, and ncmec_2022_586 to a different arrest. ncmec_2025_1116 no longer exists. NCMEC supplies 421 of the 1,123 stated cases. verified
BLOCKER
The six affordance classes are not assigned at case level anywhere in the Q1 corpus. They exist as OWL classes in CAC 3.1.0 and as hand-coded affordanceClass tags in 30 PACER JSON-LD files, 6 of which are archetype templates. That covers 24 case graphs, with 0 GenerativeSynthesis tags. The platform manifest's affordances are free text per platform, and no platform-to-class crosswalk exists in code. Any per-class case count in AfH is manual or manuscript-only. verified
BLOCKER
The manifest's harm-vector citations are broken. Of 118 case IDs cited in harm_analysis.json harm vectors, 58 still carry a stated record for that platform. 51 no longer have that platform tagged (almost all are renumbered NCMEC IDs), 5 are inferred, 3 are named-only and 1 ID is gone. verified
FOLLOW-UP
"1,875 cases with named platforms" includes generic labels. In the June snapshot, social media (780 pairs), chat (430) and Webcam platform (28) are counted. Only 1,236 cases have a non-generic named platform. verified
FOLLOW-UP
Ephemerality has no text support. "disappear" appears in 12 cases corpus-wide and none of them carry a Snapchat tag. "ephemeral", "auto-delete", "self-destruct" and "vanish" appear in 0 cases. The manuscript's Snapchat/Ephemerality signature is a capability claim, not documented misuse. verified
FOLLOW-UP
The year-over-year pattern is a coverage artifact. 84% of cases are from 2021–2026, and NCMEC has 0 cases before 2021 apart from 9 scattered. No single source spans before and after 2021 at volume. Event dates are polluted: "May 2006" (Project Safe Childhood boilerplate) is tagged as an event date in 2,358 cases. verified

H. Recommendations for AfH 2.0

Measurement design: do we need to extract affordances?

No. Extract the platform plus what it was misused for (a function bucket, with a quote) per record. Derive the affordance class through a published function → class crosswalk. Report two tiers and never merge them:

  • Documented misuse: function stated in text. Distribution → DistributionInfrastructure. AI creation → GenerativeSynthesis. "Posed as / fake account" → Anonymity.
  • Platform capability: class inferred from platform identity (Snapchat → Ephemerality). It's fine to show, but label it "capability present", never "misused".

Ephemerality, ContactDiscovery and UnmonitoredCommunication will live almost entirely in the capability tier. That is a finding worth stating, not a gap to hide.

Claims

  1. Survive: platforms recur across types, sources and eras as instruments of distribution and contact (stated evidence). Platform presence spans 2002–2026. Generative synthesis is a distinct, documented misuse (45 stated cases).
  2. Recompute: every Q1 count (1,875 / 3,128 / 858 / 136 / 881) and every Table 1 per-platform count. Kik is now 353 stated / 561 total, Snapchat 287/417, Facebook 112/318, Discord 59/129.
  3. Verify: all 118 manifest exemplar IDs, Snapchat/Ephemerality, and Kik/Anonymity (text supports it for 52 cases).
  4. Defensible temporal figures: platform presence timeline by publication year, and within-source DOJ Safe Childhood 2021–2026 shares. Drop any cross-era trend line.
  5. Rebuild: Table 1 (manifest), the §3.1 inventory, and the §7 ψ(a) table as an evidence-tiered table.
  6. §3: new denominators. Define "named platform" as non-generic. State the publication-date timeline and the coverage table.
  7. §4: split affordance signature (capability) from misuse surface (documented function), with counts per tier.
  8. §5 PACER complements Q1 with transition-level class tags. Q1 gives breadth, PACER gives mechanism. First, re-key the NCMEC PACER cases (ncmec_2023_224, ncmec_2022_586, ncmec_2023_190, ncmec_2025_1116) against current IDs. Flagged only. I did not touch the Section 5 work.
  9. Vocabulary: reconcile the three lists (CAC 8, README 7, manuscript 6). Keep six for the manuscript, but either define Coordination and CoercionLeverage as out of scope or fold them in. Add GenerativeSynthesis to iris.py.

Prioritized implementation plan

  1. Fix the freshness gate so it also hashes candidates.json against a live rebuild. Rebuild candidates and evidence. Add a test that fails on a stale pool.
  2. Give NCMEC IDs stable keys (or a crosswalk), and re-validate the manifest and PACER citations.
  3. Add a per-record misuse_function field (replacing simple_role), hand-label about 200 stratified records for precision/recall, and publish the function → class crosswalk.
  4. Rename the record harm field to charge_phrase.
  5. Rebuild Table 1, the §3.1 inventory and ψ(a) with tier columns and denominators.
  6. Optional: a role-typed date extractor with a boilerplate filter, if offense-date timelines are wanted.

Proposed figures and tables

  • T1: inventory funnel (corpus → any label → non-generic → stated / inferred / named) with exclusion reasons.
  • T2: platform manifest with a stated/total column, a function mix column, and capability vs documented class columns.
  • T3: class × tier × platform-type count, with top-platform and top-source shares.
  • F1: coverage-by-year chart (cases per source) shown under any platform-presence timeline.

Limits of this audit

  • Tier and role accuracy were not hand-validated. All counts inherit the rule-based classifier.
  • The text-cue probe reads the first 6,000 chars and only sentences that name the platform.
  • The AfH manuscript figures 858/136 were taken from the prompt. paper.txt is space-stripped, and I could not locate them there.
  • I used local caselinker.db, not production Postgres. The fingerprint matches the published snapshot's.
  • Scratch rebuild scripts and outputs are outside the repo and will be lost with the session unless copied.
